# Flatten service hostnames

Deploy the three hostname-migration commits individually and in order, not the branch tip in one switch. These are operator steps, not activation scripts. Use the normal serverone deploy procedure with the exact stage revision; keep each closure available for rollback. No VPS deployment or public DNS edits are needed for this migration.

## Before scheduling

- Record the current serverone closure, Headscale policy, baseline probes, and exact persisted settings and OIDC redirect lists. Back up tsidp state (`/mnt/SSD/apps/tsidp/lib`) and the affected app databases/configs with existing restricted permissions. Keep existing client IDs, secrets, cookie/session keys, signing keys, account mappings, subjects and data. Never put state, credentials or authorization URLs with codes in Git/logs.
- Verify the **serverone web certificate lineage** used by nginx still covers the apex, `*.polpetta.online` and `*.internal.polpetta.online`, and renews with those SANs. Keep all three through overlap **and the rollback window after retirement**. Do not change DERP DNS, certificate, or key distribution. Leave the public wildcard and the existing `internal` TXT untouched.
- Confirm public resolvers return the VPS for the new flat names and NXDOMAIN for old child names. Private split DNS uses the existing flat wildcards (LAN `192.168.2.21`, tailnet/bridge `10.0.1.6`), except explicit records. Static owners checked: apex, `www`, `internal`, `ns`, `external`, `quote-book`, `derp`; the generated raw `mc` record is distinct from `mc-runner`. Do not repoint these. Keep `internal.polpetta.online` for SSH/CIFS and its `ns` for DNS.
- Verify the installed Headscale policy and advertised `10.0.2.6/32` route restrict `10.0.2.6:443` to intended admins; it is forwarded to nginx's dedicated port 8443. Do not use ordinary ingress for admin integrations. Have a working local/break-glass login before changing auth.

## 1. Launch flat app origins (commit `hostnames: launch flat app origins`)

Before switching, add the following **exact** callbacks to the existing registrations; keep the corresponding old-host entries during overlap. No wildcard callbacks and no new clients. Inspect actual registered entries before editing. If the pinned tsidp admin UI cannot edit a client, schedule a short outage: stop tsidp, back up its state, edit only the existing entry's redirect URI array in the persisted `oidc-funnel-clients.json`, validate JSON and confirm the diff preserves IDs, secrets and all unrelated fields, then start it again. Verify it loads the updates before proceeding. Expect to sign in again after an IdP restart.

If a device or integration requires an old URL to work directly, validate its behavior before marking the launch successful.

### Access and integration acceptance

- Test from a public source, LAN without Tailscale, ordinary tailnet node, and authorized admin node. Check old and new app names with valid TLS and actual DNS. Public tests should also target the VPS explicitly (e.g. `curl --resolve HOST:443:VPS_IP https://HOST/`), without `-k`; assert no restricted backend body or redirect to an app login, not merely a non-200. Check TCP and QUIC where applicable. Tailnet-only apps should reject LAN and work on tailnet; Jellyfin/Byparr also permit LAN. Immich ML is source-restricted to the Immich server. From both IdP and app clients, check discovery/token exchanges; Radicale has its own bridge IP allowance for that purpose.
- Tailnet DNS must give `10.0.2.6` for **agent-up, grafana, headplane, jackett, mircrewrr, qbittorrent, radarr, sonarr, syncthing, t3code**, and their legacy aliases in overlap. Admin node HTTPS works via that route only; non-admin tailnet and off-tailnet clients fail. Even as an admin, force those Host/SNI names to the ordinary nginx destination and verify no admin UI is served. Confirm direct nginx `:8443` and direct backend attempts fail outside the allowed paths. DNS resolution alone is not an authorization test.
- Verify `blackbox-https` sends **both Host and TLS SNI** `jellyfin.polpetta.online` and the probe is green. Restricted backend probes are not ingress/ACL tests. Check `fritz-rebind-sync.service` and manifest; use a LAN device behind FRITZ!Box to verify new and old names resolve (admin routing is not expected from LAN). Check SSH/CIFS at the bare internal name.
- Inspect persisted Sonarr/Radarr download clients and indexers. Use the allowed bridge paths `10.0.1.5:8080` for qBittorrent (SSL off) and `http://10.0.1.8:9117` for Jackett, retaining path/key/credentials; Mircrewrr stays `http://10.0.1.135:9696` from those clients. In qBittorrent validate Web UI server domains (flat, legacy during overlap, and bridge address if required); do not loosen CSRF or auth. In Jackett/Mircrewrr replace saved FlareSolverr URLs with `https://byparr.polpetta.online`; verify an indexer that actually uses it. Test client connections, search and a download/import. Audit bookmarks/webhooks and any other saved URLs before retirement.
- In Seerr keep internal Jellyfin `http://10.0.1.10:8096`, set external Jellyfin `https://jellyfin.polpetta.online`; verify Sonarr `10.0.1.9:8989` and Radarr `10.0.1.7:7878` with SSL off and original API keys. Test Jellyfin login, library sync, and request routing. Also test Immich ML jobs, T3 Code/Agent Up link rewriting and SearXNG search.
- Repoint calendars and devices (DAVx⁵, phones/desktops, Jellyfin TVs/mobile, Immich upload clients, saved shortcuts) to flat URLs. Keep CalDAV usernames/passwords and collection paths, do not reset credentials. Test read/write/sync and a fresh Radicale setup login. `calendar-proxy` stays unchanged.

Record the successful stage-1 app launch time in UTC. The earliest retirement is 14 days from that timestamp; pause if any critical integration breaks and keep overlap until it is repaired and revalidated. If stage 1 fails, revert to the pre-stage app closure and restore affected persisted app settings. Retain old callbacks, cert coverage and state.

## 2. Cut over the single issuer (commit `hostnames: cut over the canonical OIDC issuer`)

Schedule this as one maintenance window. Pause logins, switch serverone with tsidp and all declarative consumers together, and in the same window set Immich's issuer to `https://idp.polpetta.online` and Jellyfin's **OpenID Endpoint** to `https://idp.polpetta.online/.well-known/openid-configuration`. Keep Jellyfin provider name, scheme override (`https`), client credentials and account links. Do not serve discovery at both hostnames or redirect old discovery to a different issuer. App aliases remain, but the old IdP vhost is gone; old discovery clients must be updated, not redirected.

- From authorized tailnet and relying parties, verify discovery `issuer`, authorization, token, userinfo and JWKS URLs use the flat IdP; verify a fresh signed ID token's `iss` and stable `sub` without logging tokens. Confirm external/LAN isolation of the IdP and rejection of old discovery. Existing sessions or cached discovery may need reauth/restart.
- Fresh logins: Grafana role/dashboards, Outline existing account/data, Headplane admin (and non-admin denial), ff state/PKCE, Radicale setup and existing DAV credentials, Immich browser/mobile and same library, Jellyfin SSO/linked user and playback. Observe the actual outgoing `redirect_uri` locally and compare with the registration table.
- Keep the already-flat public origins and verify their existing exact callbacks: OpenCloud `/oidc-callback.html` and `/oidc-silent-redirect.html`; giuoco-del-divertimento `/login/callback`; mc-runner and lunamultiplayer `/api/auth/oidc/callback`. Verify login and an authorized action for each. For OpenCloud check discovery via the frontend and backend, the Web UI CSP `connect-src` permits the new issuer, CORS/token exchange succeeds, and the same account/files appear. Test an existing password-protected public share and its download from off-tailnet without IdP access; test supported desktop/mobile flows separately. Do not expand app or issuer ACLs for a failed login.
- On failure switch back to stage 1 (issuer **and** declarative consumers), restore the two manual issuer settings and clear stale discovery/session caches. Keep registrations, keys and identities; restore the pre-edit client file only if the registration edit itself failed. Verify old discovery and fresh sign-ins before reopening.

## 3. Retire old app names (commit `hostnames: retire legacy web names`)

Only after the stage-1 timer and stage-2 acceptance pass, and no critical dependency still uses a legacy endpoint, switch to stage 3. It drops the old web vhosts, admin overrides, internal-zone wildcards and generated FRITZ!Box exceptions. Remove obsolete old callback URLs from the existing clients once validated, not the clients themselves. Keep the old certificate SAN and callback backup for rollback.

Verify both BIND views give NXDOMAIN for representative old child app names and random children of `internal`, but the internal apex and `ns` still resolve. Verify forced old Host/SNI cannot serve an app even with cached DNS, and flat access tiers, public shares, raw `mc`, monitoring and FRITZ!Box remain correct. If rollback is needed, restore stage 2 and old callback entries; retain certificate coverage and allow DNS caches to recover (check negative TTL and flush affected resolvers if needed). Do not roll the issuer back unless undoing stage 2 as a unit.
